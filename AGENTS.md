# AGENTS.md

Operating manual for any coding agent working in this repository. `PRD.md` says what to build. `RULES.md` says what must always be true. This file says how to behave.

## Before changing anything
1. Read `PRD.md`, `RULES.md` and `docs/DISCOVERY.md`.
2. Inspect the files you intend to touch, and the existing pattern for that kind of file.
3. If something equivalent exists, extend it. Do not duplicate it.

## Scope
- Never build a feature that is not in `PRD.md`. The "Do Not Build" list is literal.
- Never add a screen, an abstraction or a dependency the PRD does not need.
- Never write exploratory or throwaway code into the repository.
- Never create sample, demo or placeholder records. An empty list is shown as empty.
- Never weaken a requirement, a rule or a test to make something pass. Fix the code.

## Repository safety
- Reuse `getSessionUser()` for authentication. Do not write another auth mechanism.
- Reuse `db` from `src/lib/db.ts`, the helpers in `src/lib/http.ts`, and the CSS variables in `src/app/globals.css`.
- No refactors outside the task. No formatting-only changes to unrelated files.
- Never write real secrets into any file. `.env` is filled in by a human.

## Security (hard rules, see RULES.md for the checkable form)
- Every Note query goes through `notesFor(userId)` in `src/lib/records/repo.ts`. Nothing else may touch `db.note`.
- Ownership is a condition inside the query. Fetching a record and then comparing `userId` is forbidden as an authorisation mechanism.
- The internal primary key never leaves the server. Clients get `publicId`.
- A deletion and its audit row are written atomically. Never delete first and log afterwards.
- 401, 403 and 404 follow the policy in RULES.md. Do not mix them.
- The cross-user tests and the unscoped-query test must never be deleted, skipped or loosened.

## When a requirement is unclear
1. Look for an existing pattern in the repository that settles it.
2. If none, either ask, or implement the smallest safe interpretation and state the assumption in `PRD.md` section 14.
3. Never resolve ambiguity by building something more complex.

## Evidence
- Evidence files are generated by running the code: `npm run audit`, `npm run measure`.
- Never type a result, a count or a status into an evidence file by hand. Never mark a row as passing that was not run.

## Definition of done
`npm run typecheck`, `npm test` and `npm run build` pass; `npm run audit` shows every row passing; `RULES.md` holds for every changed file.
